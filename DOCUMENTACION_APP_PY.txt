 SECCIÓN 1: IMPORTACIONES (Líneas 1-7)

import os
→ Módulo del sistema operativo. Lo usamos para:
  - Crear carpetas (os.makedirs)
  - Unir rutas de archivos (os.path.join)
  - Verificar si un archivo ya existe (os.path.exists)

from datetime import datetime, timedelta
→ Manejo de fechas. Lo usamos para calcular
  las fechas de entrega en el carrito (3 días hábiles,
  2 días naturales).

from flask import Flask, render_template, request, redirect, url_for, session, flash
→ Flask es nuestro framework web. Cada cosa que importamos:
  - Flask: crea la aplicación web
  - render_template: carga los archivos HTML
  - request: lee los datos que envía el usuario (formularios)
  - redirect: redirige a otra página
  - url_for: genera URLs automáticamente (ej: url_for("index") = "/")
  - session: memoria temporal del navegador (carrito, login)
  - flash: muestra mensajes temporales al usuario

from werkzeug.security import generate_password_hash, check_password_hash
→ Encripta contraseñas para que no se guarden en texto plano.
  - generate_password_hash("123") → "pbkdf2:sha256:260000$..."
  - check_password_hash(hash, "123") → True/False

from werkzeug.utils import secure_filename
→ Limpia nombres de archivos peligrosos.
  Ejemplo: "../hack.jpg" se convierte en "hack.jpg"

from tienda_db import BaseDatosTienda
→ Importa nuestra clase de base de datos (el otro archivo).

from functools import wraps
→ Necesario para crear decoradores (@requires_admin, @login_required).

 SECCIÓN 3: FUNCIONES AUXILIARES (Líneas 20-64)
========================================================

--- allowed_image_file(filename) ---
Línea 20-21
Qué hace: Verifica si un archivo es imagen válida.
Cómo funciona:
  1. Revisa que tenga un punto (.) en el nombre
  2. Toma la extensión después del último punto
  3. La compara contra ALLOWED_IMAGE_EXTENSIONS
Ejemplo: "rosa.jpg" → True, "virus.exe" → False
¿Cómo cambiar? Agregar formatos al set ALLOWED_IMAGE_EXTENSIONS.

--- is_admin() ---
Línea 32-33
Qué hace: Verifica si el usuario actual es administrador.
Cómo funciona: Busca la llave "admin" en la sesión del navegador.
Retorna: True si es admin, False si no.
Si se rompe: Verificar que en login se ponga session["admin"] = True.

--- requires_admin(f) ---
Líneas 37-44
Qué hace: DECORADOR. Protege rutas solo para administradores.
Cómo funciona:
  1. Antes de ejecutar la ruta, pregunta is_admin()
  2. Si NO es admin → redirige al login con mensaje
  3. Si SÍ es admin → ejecuta la ruta normalmente
Uso: Poner @requires_admin arriba de cualquier ruta que quieras proteger.
¿Cómo cambiar? Si quieres agregar más roles (ej: "editor"),
crear otra función similar pero verificando session.get("editor").

--- current_user() ---
Línea 48-49
Qué hace: Retorna los datos del usuario logueado (id, username).
Si no hay nadie logueado, retorna None.

--- login_required(f) ---
Líneas 52-59
Qué hace: DECORADOR. Protege rutas solo para usuarios logueados.
Similar a requires_admin pero para clientes normales.
Uso: @login_required arriba de rutas que necesiten login.

--- carrito_session() ---
Líneas 61-64
Qué hace: Crea o retorna el carrito de compras de la sesión.
El carrito es un diccionario: {"1": 2, "5": 1}
  Clave = ID del producto (como texto)
  Valor = Cantidad
¿Cómo cambiar? Si quieres carrito persistente (que no se borre
al cerrar navegador), hay que guardarlo en la base de datos.

--- GET /carrito ---
Líneas 87-129
Qué hace: Muestra el carrito de compras con totales y fechas de entrega.
Cómo funciona:
  1. Lee el carrito de la sesión
  2. Para cada producto, busca su precio en la BD
  3. Calcula subtotales y total
  4. Calcula fechas de entrega:
     - Click & Collect: 3 días HÁBILES (salta sáb/dom)
     - Punto Medio: 2 días NATURALES (cuenta todo)
  5. Formatea las fechas en español
PROTEGIDA: Requiere @login_required
¿Cómo cambiar?
  - Cambiar días hábiles: modificar "while agregados < 3" (cambiar el 3)
  - Cambiar días naturales: modificar "timedelta(days=2)" (cambiar el 2)
  - Agregar descuentos: calcular antes de pasar "total" al template

 SECCIÓN 6: AUTENTICACIÓN (Líneas 165-215)
========================================================

--- GET/POST /registro ---
Líneas 166-182
Qué hace: Registra nuevos clientes.
Cómo funciona:
  GET → Muestra el formulario de registro
  POST →
    1. Lee username y password del formulario
    2. Valida que no estén vacíos
    3. Encripta la contraseña con generate_password_hash()
    4. Intenta crear el usuario en la BD
    5. Si el username ya existe → error
    6. Si todo bien → loguea automáticamente y redirige
¿Cómo cambiar?
  - Agregar email: añadir campo en el form y en db.crear_usuario()
  - Mínimo de contraseña: if len(password) < 6: flash("Muy corta")

--- GET/POST /login ---
Líneas 186-208
Qué hace: Inicia sesión para clientes y administrador.
Cómo funciona:
  GET → Muestra formulario de login
  POST →
    1. Lee username y password
    2. PRIMERO verifica si es admin (credenciales fijas):
       usuario: "admin", contraseña: "BrilloEterno123"
       Si sí → session["admin"] = True → panel admin
    3. Si no es admin, busca en la BD de usuarios
    4. Compara contraseña encriptada con check_password_hash()
    5. Si coincide → session["user"] = {id, username}
⚠️ IMPORTANTE: Las credenciales del admin están en texto plano
en el código (línea 196). Para mayor seguridad, guardarlas en
variables de entorno o en la BD.
¿Cómo cambiar credenciales admin?
  Modificar: username == "admin" and password == "BrilloEterno123"

--- GET /logout ---
Líneas 210-215
Qué hace: Cierra sesión del cliente.
session.pop("user", None) → borra los datos del usuario.
El carrito NO se borra (queda en sesión).

--- POST /checkout ---
Líneas 219-241
Qué hace: Procesa el "pago" y crea el pedido.
PROTEGIDA: @login_required
Cómo funciona:
